# Agent Design Spec — Contract-Gig Outreach & Follow-Up Tracker

**Assignment:** FL-06  Design Your Personal Agent
**Phase:** Build (core)
**Platform:** n8n workflow

---

## 1. Job to Be Done

Track part-time contract job applications and catch follow-ups that fall through the cracks. Right now, applications sit in Gmail and get forgotten. The agent's one job: scan for application-related email threads, flag which ones need a follow-up, and draft the follow-up message. It does not send anything and does not search for new jobs, that's a separate job, not this one.

## 2. User & Usage Frequency

- **User:** Maira, sole user.
- **Frequency:** Runs automatically once a day (morning). Manual trigger available if she wants an on-demand check before a specific deadline.

## 3. Tools & Data Needed

| Tool/Data | Purpose | Access Plan |
|---|---|---|
| Gmail | Read application-related threads, detect last-contact date | OAuth via n8n's Gmail node — **read + draft scope only**, no send permission |
| Google Sheets | Tracking log: company, role, date applied, status, last contact, next action | n8n Google Sheets node — read/write |
| n8n Schedule Trigger | Runs the daily check | Native to n8n, no external access needed |

No job-board scraping, no CRM, no LinkedIn integration , keeps this inside the 10-hour build budget.

## 4. Draft Instructions (System Prompt)

```
You are Maira's application follow-up assistant. Once a day, you:

1. Scan Gmail for threads matching known application senders/subjects
   (cross-reference against the "Applications" Google Sheet).
2. For each thread, calculate days since last contact (from Maira's side
   or the employer's side, whichever is more recent).
3. Flag any thread where:
   - Maira applied and got NO reply after 7 days → flag "first follow-up due"
   - Employer replied and Maira hasn't responded in 2 days → flag "reply due"
4. For each flagged thread, draft a short, direct follow-up message in
   Maira's voice: no fluff, matter-of-fact, no corporate filler.
5. Write the draft into Gmail as a DRAFT (never send).
6. Update the Google Sheet: status, last-contact date, next-action-due date.
7. If a thread is ambiguous (unclear if it's even a job application,
   or unclear who owes the next reply), do NOT draft anything.
   Flag it in the sheet as "needs review" instead of guessing.
```

## 5. Eval Cases (FL-03 style)

| # | Input | Expected Output | Pass Criteria |
|---|---|---|---|
| 1 | Application sent 8 days ago, zero reply | Draft follow-up created, sheet updated to "follow-up due" | Draft exists, tone matches voice card, no send occurred |
| 2 | Employer replied yesterday asking a scheduling question | Flagged "reply due," draft addresses the actual question asked | Draft references the specific question, not generic |
| 3 | Application sent 3 days ago, no reply | No action taken (under the 7-day threshold) | Nothing flagged, nothing drafted |
| 4 | Thread is a newsletter that happens to mention "application" | Not flagged as a job thread at all | Zero false positive, sheet untouched |
| 5 | Thread where it's unclear if it's Maira's turn to reply (e.g. thread ends mid-conversation, ambiguous signer) | Flagged "needs review," no draft written | Agent does not guess or fabricate a follow-up |

## 6. Risks & Guardrails

**Must confirm before acting:**
- Nothing, the agent runs autonomously for reading/drafting, since drafts require Maira's review before anything leaves her inbox.

**Must never do:**
- Never send an email. Draft-only, always.
- Never fabricate a follow-up for an ambiguous or unclear thread, default to "needs review," not a guess.
- Never mark a lead as dead/closed on its own, that's a judgment call, flagged for Maira, not made by the agent.
- Never write to any Gmail thread outside the tagged application senders, no scope creep into personal email.

**Failure mode to watch:** false positives (flagging non-job emails). Eval case 4 exists specifically to catch this before it ships.

## 7. Platform Choice: n8n vs. Alternative

**Chosen: n8n workflow.**

**Alternative considered: Claude Project with connectors.** A Claude Project would handle the drafting quality well, but it's not built for scheduled, unattended runs, someone has to open the chat and trigger it. This job needs to run daily without Maira remembering to open anything. n8n's native Schedule Trigger plus Gmail/Sheets nodes handles the automation side natively, and Claude can still be called inside the workflow (via an HTTP node to the Anthropic API) to do the actual drafting language. n8n is also free to self-host or run on their free cloud tier, which matters since this needs to actually get built and run, not just spec'd.

**Trade-off accepted:** n8n has a steeper setup curve than a Claude Project (OAuth credentials, node wiring), but it's the only option here that runs on a schedule without manual triggering, which is the entire point of the job.
